# 🪐 Sea of Mirrors 開發日誌 — 2026/10

## 📅 2026-10-09｜Unity 軸心工具開發：CustomPivotTool・QuickTreePivotTool・CustomPivotWrapperMarker

### 1. 用途
- 作用於**樹、物件，以及任何需要調整軸心的 3D 物件**（例如 Tree、House、Cube）。
- 不修改 Mesh 資產本身：工具會建立一個空的 **Pivot Wrapper**（物件名稱 `{物件名}_Pivot`）包住模型，由 Wrapper 的位置當作新的軸心。
- 所有操作皆可用 Cmd + Z（Mac）／Ctrl + Z（PC）復原。

### 2. 三支腳本

| 腳本 | 類型 | 選單位置 | 用途 |
|---|---|---|---|
| `CustomPivotTool.cs` | Editor 視窗 | Tools → Siohuhu → 自訂軸心與歸零工具 | 單一物件的軸心設定：快速預設對齊、手動拖曳／數值微調、歸零 |
| `QuickTreePivotTool.cs` | Editor 視窗 | Tools → Siohuhu → ＊＿＊樹木底部軸心與歸零 | 樹木／植物專用，**可多選批量**，一鍵設定底部軸心並歸零 |
| `CustomPivotWrapperMarker.cs` | MonoBehaviour（空元件） | — | 標記哪些物件是 Pivot Wrapper，沒有任何執行期邏輯 |

**CustomPivotTool 主要功能**
- 啟用／停用開關（可停用並關閉視窗，不會控制新選取的物件）。
- 「快速預設對齊」：Center、Bottom_Y、Top_Y、Left_X、Right_X、Back_Z、Front_Z。
- 「初始化底部軸心」：重置 Offset 並套用 Bottom_Y，一鍵完成。
- 「手動拖曳／數值微調」：Scene 內紅／綠／藍箭頭拖曳，或輸入 Offset 數值，確認後才套用；可選擇是否隱藏 Unity 原生 Move Tool。
- 歸零選項：
  - **底部軸心歸 0（Y 向上）**：先把 Pivot 設在整個資產最低點，再把 Pivot 移到世界原點。
  - **中心軸歸 0**：先把 Pivot 設在整個資產中心，再把 Pivot 移到世界原點。
  - **只移動目前軸心到世界原點**。

**QuickTreePivotTool**
- 一個按鈕「一鍵設定底部軸心並歸零」：軸心對齊底部（-Y），並把世界座標與旋轉歸零（0, 0, 0）。
- 支援同時選取多個物件批量處理。

### 3. 作業流程
1. 美術在 Blender／Maya 建立物件並匯出
2. Unity 成員匯入 FBX
3. 在 Hierarchy 選取物件（例如 Tree、House、Cube）
4. 開啟 CustomPivotTool
5. 按「初始化底部軸心」
6. 需要時手動微調
7. 按「底部軸心歸 0（Y 向上）」
8. 儲存 Scene 或 Prefab
9. 將 `.prefab`、Scene 與工具腳本一起提交版本控制

### 4. 放置位置與版本控制
- `CustomPivotWrapperMarker.cs` 必須放在**非 Editor** 資料夾（建議 `Assets/Scripts`），且檔名必須與類別名稱一致；放進 Editor 資料夾或寫在別的檔案裡，場景中的 Marker 會變成 Missing Script。
- 兩支 Editor 工具建議放在 `Assets/Scripts/Editor/`。
- Sandbox 的 `.gitignore` 與備份腳本只保留 `Assets/Scripts`、`Scenes`、`Prefabs`（與必要設定），放在其他資料夾（例如 `Assets/Editor`）的工具腳本**不會被備份**。

### 5. 注意事項
- **QuickTreePivotTool 會把處理過的物件移到世界原點並歸零旋轉**。多個物件同時處理會全部疊在原點，適合用來製作 Prefab 資產；**不要對已經擺放在場景中的物件使用**。
- 兩支工具目前以物件本地座標計算「底部」。若匯入的 FBX 根物件帶有旋轉（例如 -90°），底部可能不是世界最低點（尚未實測，待確認）。
- 選取的若是 Prefab 實例內部的子物件，Unity 不允許更換父層；請改選最外層根物件，或先 Unpack。
- **待確認：Editor 工具的資料夾位置**。工具日誌寫 `Assets/Editor/`，但 Sandbox 的 `.gitignore` 與備份腳本只保留 `Assets/Scripts`，放在 `Assets/Editor/` 的腳本不會被備份或提交。需統一為 `Assets/Scripts/Editor/`，或在白名單加入 `Assets/Editor`。
- **待確認：DrawCameraRay 的重繪機制**（`SceneView.duringSceneGui`）是否已在目前使用的版本中。

### 6. 協同注意事項
1. `CustomPivotTool.cs` 專案內只放一份，放在 `Assets/Scripts/Editor/`。
2. `CustomPivotWrapperMarker.cs` 放在非 Editor 資料夾（例如 `Assets/Scripts`），檔名須與類別名稱一致。
3. 調整完成後，儲存 Scene，或把 Pivot Wrapper（連同模型）儲存成 Prefab。
4. FBX 重新匯入後，Wrapper 不會被刪除，但軸心位置不會自動更新；模型尺寸或形狀有變時，需確認軸心是否仍在底部。
5. 工具不用時，取消「啟用 CustomPivotTool」或關閉視窗，就不會對選取的物件顯示手把，也不會自動建立或修改任何物件。
6. 工具本身只在編輯器運作，不會進入遊戲；已建立的 Wrapper 與 Marker 會以一般空物件存在於場景中。
7. 分工：美術負責模型（FBX），Unity 成員負責 Pivot 與 Prefab 整理；工具不修改原始 Mesh，兩邊不會互相覆蓋。

### 7. 修正歷程（簡化）

**CustomPivotTool**
- 初版：Unity 無法直接改 Mesh 內部軸心，改用空父物件當 Pivot 容器；自動計算 Mesh 幾何中心；位置與旋轉歸零；支援 Undo；快捷鍵 Option + C。
- 修正 1：自訂軸心後不在 -Y 底部 → 改用 `sharedMesh.bounds`（局部座標），不混用 `Renderer.bounds`；處理 lossyScale 造成的縮放偏移。
- 修正 2：新增手動移動軸心（Scene 視窗拖曳、Inspector 數值微調）。
- 修正 3：手動拖曳無效、套用後跳回中心 → 原因是 Offset 為零時會走回預設方向；改為「快速預設」與「手動」分頁，手動 Offset 獨立保存。
- 修正 4：改用 **Pivot Wrapper**：不修改 Mesh、不再自動改 BoxCollider、重複套用會重用 Wrapper、保留物件原本的世界位置、旋轉與縮放。
- 修正 5：針對 Blender／Maya 匯入的模型：合併整個階層的 Mesh Bounds，Bottom_Y 以整體最低點為準；預設 Pivot 方向為 WorldYUp，可切換 KeepObjectRotation。
- 修正 6：用 `CustomPivotWrapperMarker` 辨識 Wrapper（不再只靠名稱）；選到 `Object_Pivot` 時自動找到內部模型；相容舊的 `_Pivot_Pivot`；Offset 不再每次重繪被重設。
- 修正 7：問題是 Unity 原生手把與自訂手把重疊、套用後 Wrapper 移到世界原點會破壞「軸心在模型底部」、下次讀取 Offset 軸心會跳動 → 邏輯改為：套用軸心時 Wrapper 放在模型底部且物件不動；手動調整時隱藏原生手把；世界歸零另做獨立操作。
- 修正 8：不再使用 PositionHandle，青色球體可直接拖曳並即時更新；手把位置直接讀取實際 Wrapper；數值修改即時套用；保留紅／綠／藍方向提示線。

**QuickTreePivotTool**
- 初版：開啟視窗就是一個大按鈕；預設 Bottom_Y；一鍵完成 Pivot 建立與世界歸零；支援多選批次處理。
- 修正 1：檔案配置：Marker 放一般資料夾（避免打包時找不到元件），Editor 工具放 Editor 資料夾。
- 修正 2：重複執行失靈 → 每次依最新世界頂點重算底部；重新定位 Wrapper 前先把模型安全脫離再掛回，避免位移累加；限定只能選最上層物件，選到子物件會提示並中止。

**DrawCameraRay**
- 初版：參考 Blender／Maya 的視錐體標示，自動讀取 Camera（透視與正交），繪製視窗四角線、外框與頂邊三角形；`[ExecuteAlways]`。
- 修正 1：參考線與 Simulator 比例不一致 → 編輯器內 `Screen.width/height` 會讀到 Scene 視窗解析度，改用 `Handles.GetMainGameViewSize()`。
- 修正 2：切換 Simulator／Game 時參考線沒即時更新 → Scene 視窗不會自動重繪，改用 `SceneView.duringSceneGui` 強制重繪。
- 修正 3：正交相機改畫成長方體；找不到 Camera 時退回 Manual Lens；讀取 Cinemachine 的 ModeOverride；只有 Cinemachine 時比例沿用 `Camera.main`；新增 Use Game View Aspect（預設關閉）；元件查找改為快取。腳本放 `Assets/Scripts/`。

### 8. 資產交付規範（Blender／Maya → Unity）
流程：先在 Blender／Maya 把資產整理正確，Unity 腳本只做最後補救與檢查。

**Blender 匯出前**
1. 選取資產根物件
2. Ctrl + A 套用 Rotation、Scale
3. 將 Origin 設定到物件底部
4. 確認模型底部為 Y = 0
5. FBX Export：Forward = -Z Forward、Up = Y Up、Apply Transform 依專案統一設定（不要每個資產用不同設定）

**Maya 匯出前**
1. Scene Up Axis 使用 Y
2. 檢查 System Units
3. Freeze Transform
4. 將 Pivot 移到模型底部
5. 根物件位置、旋轉歸零，縮放歸一
6. FBX Export：Up Axis = Y，Units 與場景一致

**Unity Import 檢查**
- Scale Factor 依來源單位設定、Convert Units 避免重複轉換、Bake Axis 全專案統一、建議開啟 Preserve Hierarchy。
- 1 unit 對應 1 公尺；不要在 Blender／Maya、FBX Export、Unity Import 三處重複縮放。

**CustomPivotTool 適合處理**
- 根物件 Pivot 不在底部
- 資產有多個 Mesh 子物件
- Blender／Maya 無法快速整理 Pivot
- 需要在 Unity 中統一 World Y Up
- 需要以整個階層的最低點作為底部

## 📅 2026-10-20｜筆觸取樣掃描測試：mm 與 px 的換算

- 掃描規格：4000×4000 px、1200 dpi、48 位元（掃描器有 48 位元選項）。
- 換算：1 英吋 = 25.4 mm = 1200 px，約 47 px 對應 1 mm，可以把真實筆觸大小換算成畫面上的像素。
- 同時取樣並渲染灰階的過渡層。
- 問題：轉換成數位之後，顏色與質感還是有落差，必須換墨水與顏料，重新製作。
- 備註：這類試錯細節只記在 devlog，貼文只分享換算的樂趣（依 10/16 的做法）。

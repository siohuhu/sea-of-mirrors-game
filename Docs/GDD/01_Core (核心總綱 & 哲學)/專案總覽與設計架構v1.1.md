## 1.1專案總覽與設計架構 (Project Architecture)

專案採用自上而下（Top-Down）的設計藍圖，確保世界觀、體驗感與技術層面高度一致：

Vision (願景)

    │

    ▼

 Experience Flow (玩家體驗)

    │

    ▼

 Core Loop (玩法循環)

    │

    ▼

 World Flow (世界運作)

    │

    ▼

 System Flow (系統實作)

    │

    ▼

 Technical Architecture (技術架構)

- Vision (願景)：心靈鏡像與非同步陪伴的核心價值
- Experience Flow (玩家體驗)：開場（月/海/霧）至場景顯化的感官旅程
 * **Experience（體驗）：** 未知 ➔ 凝視 ➔ 迷失 ➔ 觸碰 ➔ 顯現 ➔ 相遇
 * **Visual & Sensory（視覺與感官）：** 
 * 夜與月 ➔ 鏡之海 ➔ 迷霧 ➔ 觸碰（撥開迷霧：伴隨風聲、呼吸聲、霧氣與光暈過場） ➔ 場景顯現 ➔ 相遇
 * **Core Elements（核心意象）：** 月 ➔ 海 ➔ 霧 ➔ 場景 ➔ 白鹿（NPC）- Core Loop (玩法循環)：走→停→摸→聽與月神卡凝視的閉環
- World Flow (世界運作)：數值企劃 / 世界觀企劃：28天月相、律動、霧與四大元素運作法則
- System Flow (系統實作)：FigJam 系統流程圖、介面 Wireframe、FTUE 與 SavePoint 觸發邏輯。
- Technical Architecture (技術架構)：Unity 架構、Firebase、Game Center 與輕量效能優化。

設計概念(Design Philosophy)
Sea of Mirrors 的每一行程式碼與技術架構（Technical Architecture），
都是為了支撐系統運算（System Flow）；每一個系統機制，都在維護世界的自然運作（World Flow）；
世界的運作推動了玩法的循環（Core Loop）；玩法的循環創造了沉浸的體驗（Experience Flow）；
而所有的體驗，最終都在回應作品的核心願景（Vision）。」

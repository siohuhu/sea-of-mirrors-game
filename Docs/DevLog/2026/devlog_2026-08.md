## 3. ✅ Apple Sign In／Game Center／Firebase 匿名身份技術方案：最終定案（2026-08-03）

**背景**：FTUE 第 2 頁流程圖經過三輪迭代（05→06→07），逐一解決先前提出的技術疑慮，此版本為最終確認版，可交付工程師實作。

### 核心架構（Firebase 匿名驗證 × Game Center 雙軌聯動）

**Phase 0 全域初始化**：進入遊戲瞬間統一執行 `signInAnonymously()`，確保 `currentUser` 存在且零阻力進入 FTUE（不論網路狀態，優先建立 Local Session）

**分支1（iOS 登入 Game Center）**
1. 背景取得 GameKit Credentials
2. 執行 `currentUser.linkWithCredential()` 完成綁定
3. 例外處理（Collision）：若 `CREDENTIAL_ALREADY_IN_USE`（該 Game Center 帳號已於其他裝置綁定過），改執行 `signInWithCredential()`，直接切換登入該帳號並觸發【觸發點4：跨裝置同步／衝突復原】

**分支2（離線／未登入 Game Center）**
保持匿名狀態，使用 Firebase Native Offline Persistence 支援本地狀態，過幾天於【觸發點3：雙階段簽到】或選單引導補綁定（即「微光記憶」兩階段漸進式引導）

**底層**：統一進入 Firebase DB（Firestore／Realtime DB），前端所有觸發點（社群分享、商人交易、雙階段簽到）與專案 sea-of-mirrors-e1224 的後端資料庫統一

### 四個觸發點（重新編號，不再與其他編號衝突）
1. 社群分享 → 微光記憶：背景 Snapshot 寫入
2. 流浪商人交易 → 微光記憶：交易完成即時強制寫入 Cloud SavePoint
3. 雙階段簽到 → 微光記憶：資產變動／驚喜感 SavePoint
4. 跨裝置同步／Game Center 登入衝突復原：自動讀取／喚醒

### 技術驗證歷程（三輪迭代解決的問題）
- **v05→v06**：解決「跨裝置同步」措辭矛盾（靜默偵測 vs. 跳出提示邏輯不一致）、Game Center／Firebase 技術路徑不一致問題——確認為 Game Center 提供憑證來源、Firebase 為統一後端，兩者非互斥
- **v06→v07**：解決 `linkWithCredential()` 前置條件問題——需先有 Firebase session（透過 Phase 0 全域 `signInAnonymously()`）才能呼叫 `linkWithCredential()`；補上 `CREDENTIAL_ALREADY_IN_USE` 例外處理；觸發點編號重複問題（原本兩處都用「觸發點3」）已重新編號為 1–4，不再衝突

**技術可行性依據**：Firebase 官方文件確認 `GameCenterAuthProvider.getCredential()` 為官方支援 API，需在 Firebase Console 啟用 Game Center 登入提供者；2023 年後 Firebase SDK 已改用 `gamePlayerID`／`teamPlayerID` 取代舊版 `playerID` 作為主要識別碼，**指定採用 Firebase SDK 10.5.0（或以上版本）** 以確保支援新識別欄位。

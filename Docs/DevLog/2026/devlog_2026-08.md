## 10. 🔄 Core Loop 核心閉環結構定案（v04_3_1）（2026-08-13）

**三種節點性質，取代原本連續編號（1–6）**：
1. **可重複執行的步驟**（Walk/Stop/Touch/Listen）——保留編號，分鐘級單輪閉環
2. **隨時可能觸發的關係節點**（伴寵締結・反饋/命名/關係深化）——降層級為節點、拿掉編號，因為它是四動作閉環持續運作時隨時可能發生的累積性互動，非排隊等候的階段性步驟
3. **不同時間尺度的背景循環**（月神卡凝視、月相・世界流動）——拿掉編號，因兩者分屬並行疊加機制與28天週期的另一尺度循環，皆非與1–4同順序、同顆粒度的步驟

**判斷依據**：原本連續編號會讓人誤以為所有節點同屬同一時間顆粒度，混淆了分鐘級與月級兩種循環，拿掉編號修正表達上的潛在誤導，因果箭頭與連接文字完整保留。

**用詞微調**：「28天月相/世界改變」→「月相・世界流動」；「獲得：記憶碎片/寫入手帳」→「旅人碎片・與旅人留下的記憶相遇」¹；「伴寵締結/手帳記錄（Taming & Journal）」→「伴寵締結（反饋/命名/關係深化）」，去英文機制詞，補上 warmth 長期累積概念。

> ¹〔校閱標註〕原文用「記憶碎片」，已統一改回 GDD（07-13）定案的正式術語「旅人碎片」，Core Loop 語境不再另立新詞。

## 13. 🏗️ Technical Architecture v0.1.3.1 檢查與用詞修正（2026-08-19）

在 System Flow（SYS-A/B/C）基礎上，這版擴充完整技術閉環：新增 **Outputs（輸出層）**（世界回應分流至場景與氛圍／動態遭遇：小箱車或殘影／聽覺語境三種輸出）與 **Persistence/Data Layer（持久化層）**（Local State/Cache、SavePoint/Snapshot、Companion Registry、World State DB），與 08-03 已定案的 Firebase/Game Center 技術方案路徑一致。

**REV 節點補充註解**：確認「REV」為 Return / Echo / Variation 三字首縮寫（純簡寫命名，非逐字對應下方「探索留痕/記憶回拆/狀態養分」三個關鍵詞，兩者獨立）。REV 是 Outputs 三節點匯聚後的回流節點，將輸出內容回饋進 SYS-B 循環或 SYS-A 世界狀態，形成「世界回應玩家→回流養分→影響下一輪世界狀態」的閉環。

**手稿溯源**：最初手繪草稿（202608_TechArch_v0.1.1_Draft）上原本寫的是「多模態．(sensory multimode) outputs」，括號內已注記「sensory」（感官）這個更貼近體感的英文詞，只是後來畫成正式圖表時中文簡化成了「多模態」。本次「多感官回饋」的修正實質上是回歸最初手稿的感官語感，非憑空新方向。

**檢查結果**：月相矩陣天數對應、小箱車用詞、SYS-B 內部決策點註解皆與現有設定一致，無星座相關用詞。**待辦**：圖面補上「多感官回饋」與 REV 全稱正式註解。

## 🦊 火元素｜狐狸

**背景設定**
- 從遙遠的麥田與玫瑰花園流浪至鏡之海,部分記憶已遺忘,僅模糊記得一位來自遙遠星球的朋友,身影已不可辨。
- 狐狸本身也是**旅人碎片**之一——牠並非全知的導師,而是也在學習如何締結羈絆。

**外觀設定**
- 體長約 60–75 cm,尾長約 50–60 cm,肩高約 40–50 cm。
- 毛髮捲成一束一束,遠看似火焰,近觸卻是柔軟的。
- 蓬鬆尾巴末端在濃霧中會凝聚出淡藍綠色火花,溫度低,可作霧中導引之用。

**性格**
- 生性多疑但好奇心強;多數時間獨自活動;聽覺與嗅覺極為發達;神情帶一點慧黠。

**核心秘密（三個)**
1. 每一段關係都是獨一無二的
2. 用心去看,而非只用眼睛
3. 關係伴隨代價與責任

> 對應小王子的狐狸寓言,重新用鏡之海的世界觀詮釋;三個秘密將透過月神卡與旅人碎片呈現(對應方式需與其他伴寵整合後統一設計)。

## 🐺 水元素｜無名之狼（黑狼)

**核心命題：直面黑暗,而非戰鬥**
- 黑狼並非外來的怪物,而是旅人內心孤獨與壓抑情緒的具象化。
- 設定核心：恐懼、憤怒或消沉的意志,不只會滋養自己內心的黑狼,也會養大遇見之人心中的那一隻。
- 最可怕的黑暗不是做壞事,而是**失去自我認同**——忘記自己是誰、被體制/秩序同化吞噬。
- 成長不是消滅黑暗,而是透過勇氣與愛,直面並整合內心的恐懼與孤獨,找回自己的名字與自性。
- 「忘記名字」的自我認同危機,本身即為一則旅人碎片。

**背景故事**
- 狼本不是怪物,而是記憶的守護者。當旅人因恐懼、創傷或順應外界規範放棄部分自我時,那份被拋棄的情感與記憶沉入鏡之海,化為失去名字的黑狼。

**化解機制**
- 旅人不逃跑,而是停下腳步,直視暗影雙眼中的恐懼。
- 狂暴是因為遺忘,咆哮是因為孤獨。
- 核心台詞方向：「我不怕你,我知道你只是很孤獨。」
- 直視以愛與凝視,還原真名——狼不再是吞噬旅人的怪物,而是陪伴找回自性的靈魂夥伴。

**任務配對構想**
- 「月光與影」:黑狼代表被剝離、遺忘在暗處的野性與孤獨(陰影);月亮代表水底沉靜、等待被拼湊齊全的記憶心核(自性)。

**外觀 / 物理設定**
- 官方名稱：無名之狼(The Nameless Wolf);毛色定名**幻影黑**。
- 肩高約 70–80 cm,四肢修長、軀幹緊湊。
- 身體是水與空氣的混合體,可任意改變形狀——時而膨脹狂暴,時而縮小,時而化為透明安靜的黑影。
- 沒有固定自我,容易吸收外在能量:融入負物質會膨脹成怪物,吐出負物質則回到平靜半透明的水狀態(呼應其內心狀態)。
- 身體會隨吸收的物質變化,有時僅頭部顯現,身體消失。
- 除了半透明狀態,也可能凝聚成一顆水球——心境的具現化。

**視覺草稿進度**
- 已產出多版概念稿,持續在「野性感」與「通透感」之間找平衡:黑色範圍加大會增強猛獸感與辨識度,但會犧牲半透明、隨時可能消散的虛無質地。
- 下一步方向：嘗試分區處理(如頭頸部維持深色與野性,軀幹後段維持通透),讓兩種質地在同一畫面共存,而非互相稀釋。

## 🦉 風元素｜穴小鶚 / 飛行煤球

**基本設定**
- 又稱貓頭鷹、小煤球(Flying Soot-balls)。
- 身高約 19–25 cm,翼展約 50–60 cm;身體纖瘦、尾巴極短,蓬鬆棕藍色羽毛外觀似煤球。
- 雙腳與身體比例相比顯得極為細長;比起飛行,更喜歡用跑的。

**核心設定：三位一體**
- 縮在一起時是一顆完整的毛球;分開時,每一隻都是正在努力療癒自己的靈魂。
- 觸發「微小直覺」的超越功能——象徵無意間閃過的直覺與未被言語化的念頭,是意識階梯最底層、最接近現實意識的微小閃光,代表心靈最原始、未受馴化的生命力與純真直覺。

**靈感感知(Insight Sensing)**
- 對「未寄出的信」與「未說出口的心聲」極為敏感。
- 旅人在鏡之海邊迷茫時,飛行煤球會率先飄向某個方向,提供微小的引導。
- 任何一封信(潛意識訊息/念頭)的寄出,都是同一心靈的完整循環：尋找方向 → 封印 → 送達。
- 平時只是縮在樹洞的黑毛球;風吹過或心中閃過某個念頭時,會「啵」地張開細長雙腳,像蒲公英般漂浮於空氣中。

**郵局場景設定**
- 郵局外觀為巨木樹根下的古老地穴,樹洞與地下通道交織的奇妙空間。
- 三隻煤球是鏡之海的郵差,平時縮在樹洞最深處的木苔榻上打瞌睡;信投進樹洞口信箱時,便踮著細長小腿從樹根縫隙探出頭收信。
- 收發信內容:一封永遠無法送達的情書、一雙臭襪子、一個聲音、一句話、一首歌⋯⋯皆為旅人碎片。
- 郵局有一只「亂嘈嘈方向針」,指針永遠亂轉,不指東南西北,只指風吹過的方向;送信全靠這只任性的指針,指向「未竟之地」。
- 寄件者為上一代旅人,收件者為下一個踏入鏡之海的旅人、或仍在流浪的旅人。
- 這是郵局最隨性的信:郵差們不會主動去送,而是等待風帶來低語。

### 🤖 土元素｜小土豆 Little Potato

**外觀設定**
- 身高約 60–75 cm;方正箱型身體,鹵素燈式圓形發光眼睛(以電流加熱鎢絲發光、鹵素循環讓蒸發鎢原子回到燈絲),鉚釘細節,偏冷綠藍灰單色金屬質感。
- 側面横紋通風口暗示機械式運轉;記憶體設定約 256 kb。
- 正面方形面板可打開,放入收集的物品(毛線球、鳥窩、旅人碎片),同時承接讀取與收納。

**移動與表達**
- 移動方式為滑行而非行走:足部貼地不動,僅上半身以腿部關節為軸心做剛體傾斜,非多關節彎曲,行動遲緩但可靠。
- 眼睛燈光明暗表達「內在狀態」,傾轉姿態表達「外在注意力/在乎什麼」,兩者可組合呈現(如旅人靠近時緩慢傾轉向上、燈光漸亮)。

**核心設定**
- 由某位旅人親手製作、留在鏡之海裡,承載那位旅人的意念/技藝/情感投射——屬於「被賦予靈魂的器物」的被創造型存在,與自然存在型的狐、狼、貓頭鷹不同,不依附任何特定旅人的創造行為而獨立存在。
- 天生帶著「被留下」「依附」的孤獨感與使命感,是情感投射的實體化:當一個人心靈深度投入於某件造物,該物體便成為心靈能量(Libido)的載體。
- 受限於極小記憶體,會逐漸模糊創造者的名字;新旅人的「重新命名」,是將這份客體關係重新統合進自己心靈的過程——命名不只是承接關係,也是傳承。
- 小土豆本身就是一份「同行足跡」的具現化:把原本被動的信件/訊息,升級成一個會自己滑行、會傾轉身體、會替你裝著毛線球與鳥窩的完整生命體。玩家自己在遊戲中的存在(探索、命名、關係深化),終將成為未來某個時刻的同行足跡,呼應移動哲學「留下痕跡」與 Vision「心靈鏡像」在不同尺度上的展現。

**設計金句**
- 「存不進記憶體的,就用胸膛好好裝著。」——對數位時代的溫柔反諷:最珍貴的情感足跡不需要變成龐大數據,實體的保管與觸碰才是心靈最笨拙卻堅固的連結。

**對話範例(延遲反應之美)**

### 🦌 全域｜白鹿（白之心）White Deer

- 定位為鏡之海**全域系統 NPC**,不屬於四隻伴寵之一,不受限於任何區域——代表「自我的原型」,是引導靈魂穿過迷霧的心靈指引者,是鏡之海(潛意識海洋)本身在理智與混亂交界處凝聚出的光影形體。
- 兩種外在顯化型態:幼鹿(身長 90–100cm,肩高 40–50cm,參考白色梅花幼鹿的外觀)與成年鹿(身長 110–120cm,肩高 90–110cm,鹿角呈自然樹枝狀,不拘泥特定鹿角型)。
- **全域潮汐與氣候總控**:白鹿的出現與離開,決定鏡之海的漲潮(情感壓抑/雜訊升高)與退潮(心靈清晰/記憶顯露)。
- **同行足跡的最終記錄者**:記錄每位旅人穿過鏡之海的靈魂軌跡;旅人離開時,白鹿會將其名號、信件與伴寵羈絆昇華轉化為全域碎片,再度灑落,成為下一位旅人抬頭可見的世界背景。
- 不干涉玩家與伴寵互動,只在心靈對立達到頂點時現身,作為和解與昇華的見證者。
- 白天行走於鏡之海,夜晚化為半透明、漫步天地間的光影形體(Night-Walker);不對話,不參與仇恨或愛戀,生命的誕生凋零只是牠踩過地面時自然起伏的現象。

### 🧩 第一次遊戲機制討論:鏡射認知 Bug

本週首度從「伴寵/世界觀」討論轉向「玩法機制」討論。

**核心設計前提**
- 人類大腦習慣把眼前的人或鏡中影「水平旋轉 180 度」來代入對方視角(心理旋轉,Mental Rotation),卻誤將這個自己腦補的錯覺,歸咎給鏡子——以為是「鏡子把左右顛倒了」,實際上鏡子沒有做任何水平旋轉。

**機制設計:腦補轉動 vs. 深度實體(Mental Rotation vs. Z-Depth)**
- 大腦的錯覺(XY 平面):玩家若把鏡中世界當作旋轉後的房間去解謎,會不斷碰壁、走入死胡同。
- 物理與心靈的真實(Z 軸):放棄水平旋轉假想,意識到鏡中影只在 Z 軸(深度)被穿透與翻轉,隱藏道路才會顯現。
- 視覺語言:鏡面平時像一層薄水膜或一粒細沙,是 2D 平面圖騰;觸發 Z 軸機制時,內部深遠空間像手風琴一樣被拉開或推平——「一粒沙裡藏著無窮的深度」成為可操作的視覺語言。

**心流體驗曲線(四階段)**
1. 微微的困惑——習慣性左右踱步,無操作壓力
2. 靜默的提示——「一粒沙一世界」式的詩意謎語,觸發思考
3. 輕盈的操作——面對鏡面單次觸控或按住微光提示,極簡直覺動作
4. 心靈的頓悟——空間展開,產生觸動與心流

> 此設計方向已定案,將作為之後月神卡任務設計的核心參照,實際落地時可能需要驗證與調整。

**月神卡設計目標(延伸自本次討論)**
- 遊戲深度/機制份量會直接影響體驗:玩法不能太難,但要有差異化的方式帶來成就感。
- 終極目標:希望玩家會說出「我很喜歡這張月神卡的故事」——差異化的關鍵應落在每張卡各自獨特的頓悟內容/情感質地,而非難度堆疊。

**技術與效能考量**
- Unity 中即時半透明材質效能成本高,因此刻意花時間測試油性色鉛筆＋水彩繪製材質,用貼圖模擬透明效果,取代直接依賴引擎層級的透明度設定。
- 核心原則:流暢的效能/遊玩體驗優先於故事品質——故事再好,體驗卡頓一樣沒用;此原則來自第一款遊戲(合約、運營、人、開發體驗)的綜合深刻收獲。

### 🧩 核心解謎機制企劃草案 v0.1：2.5D 摺疊與無縫遮擋

首次針對「2.5D 摺疊與無縫遮擋」機制展開討論(與先前的鏡射認知 Bug/Z軸機制並行發展)。

**核心概念**
- 放棄傳統「黑畫面淡入淡出」轉場,改用 2.5D 紙藝對折與外層 3D 結構體作為視覺遮蔽物(Occluders)。
- 在固定正交視角下,利用空間對折產生的螢幕空間死角,實現角色在「實體狀態」與「半透明虛體(水/空氣)狀態」之間的無縫切換,踏上懸空的隱形路徑。

**玩家體驗循環**
觀察空間困境 → 操作對折機關 → 利用遮擋走入死角 → 狀態切換踏上隱形路徑 → 展開地圖解開空間。

**遮蔽物系統**
- 2.5D 摺痕(Fold Crease):地圖對折時產生的紙張邊界、厚度陰影或撕邊。
- 關卡視覺引導:圖騰拼接(Pattern Matching)——未對折時兩側手繪圖騰斷開,對折後圖騰接續。

**參考圖像(建築鳥瞰/攤平地圖繪畫)**
- 拉吉普特風格寺廟宮殿鳥瞰畫、鄂圖曼細密畫風燈塔小島、宮殿花園鳥瞰圖(水面有船)——皆為傳統繪畫「非透視、多視角並置」的空間表現手法,作為摺疊遮蔽機制的美術原型參考。

**設計取捨**
- 畫面維持 2.5D/3D 混合;希望玩家不是在「打卡」,任務需帶一點輕解謎的樂趣與成就感。
- 月神卡不只是收集品,正在嘗試讓卡面對應伴寵故事的地圖——卡面構圖本身應同時說故事、也暗示玩法。
- 謎題難度需對應月神卡意義與旅人碎片內容,不能太難也不能太簡單,不走經驗值數值堆疊的路線,而是追求「有意義的玩」,並希望玩家之間可以互相交流解謎心得。
- 目標:希望玩家會說出「我很喜歡這張月神卡的故事」。

### 🪞 鏡射穿越機制延伸討論

延續鏡射認知 Bug(Z軸 vs. XY水平旋轉)的討論,進一步發展出具體座標驗證與穿越邏輯:

- 手繪座標圖驗證:以 A / -A 兩顆分開放置的實體物件,對應鏡射前後的位置關係,搭配固定觀察視角(V)與遮蔽死角,驗證「Z軸翻轉、非水平旋轉」的空間邏輯是否能在畫面上站得住。
- **A 與 -A 代表鏡射穿越**:穿過鏡面不只是視覺對稱,而是真正的空間轉換,並將加入「負值(負空間)條件」的任務設計。
- **儀式化的引導動作**:穿越並非單純的通過,而是需要玩家一開始先觸碰倒影、撥開謎霧去感受方向,才能觸發穿越——這個「觸碰倒影、撥霧感受」的儀式,會是玩家在整個遊戲中反覆練習的動作,具體形式每次出現時會不同,但底層「引導」概念貫穿全遊戲、盡量運用到所有場景。
- **遊戲進入點設計**:玩家進入鏡之海本身,就是從觸碰倒影開始,同時暗示心理與物理層面的感受。
- 盡量不做明說明教學,讓玩家自然地去玩、去嘗試。

### 💡 機制設計哲學總結

本次討論收斂出以下核心設計原則:

1. 機制盡量根植於真實的人類心理、身體/生理反射、大腦認知差異(鏡射認知 Bug 即一例)。
2. 操作動作應保持下意識、直覺,不需複雜指令;但意義與理解仍需要玩家思考。
3. 一切為了讓玩家享受過程,而非執行複雜指令——這是過去大量試錯後收斂出的經驗。
4. 快速迭代優先於一次到位:執行錯誤不等於失敗,重點在於能否更早、更快地失敗,並在失敗後真正修正,走到下一次的成功(「100 次失敗後的第 101 次成功才是關鍵」)。

**具體歷史教訓佐證**
- 過去一個專案為了與其他遊戲做出區隔,設計了大量複雜操作動作,測試時大部分受測者做不出來,需要花時間說明,受測者的熱情雖未明說但明顯流失;更危險的是,玩家回應變少容易被誤讀為「可行」,導致團隊進一步加入更複雜的操作,問題被放大。
- 過去也曾設計一個心理測驗網頁:受測者無法準確說出自己的不適點,因此改為讓使用者像玩遊戲一樣輕鬆點擊,再將結果量化分析,成功在不需要受測者直接說出想法、心理壓力也較低的情況下,得出真實想法。這套「行為優先於語言、量化優先於主觀表達」的方法論,是長期摸索、沒有前例可循下建構出來的,未來新專案也會延續同樣的做法。
- 過去也有程式端案例:工程師為了盡快結案,大量內容被寫死;另一案例則是使用了高效能但記憶體用量大的公式,雖然效能好,卻完全無法事後修正調整——效能與可迭代性之間的取捨,若只追求前者、犧牲後者,長期反而會拖累專案。

### 👥 團隊協作與備案規劃

- 目前部分時間投入於面試程式與美術人員;由於工作流程與制式方法不同,參與者常對「這個團隊為什麼這樣做」感到疑惑。
- 遊戲的 GDD 需要寫得非常清楚,目前的疑惑主要出現在「工作流程」本身,而非遊戲設計內容。
- 團隊流程已全面轉為線上,AI 工具帶來很大幫助,盡量將一切轉移到雲端;面試參與者需要能真正投入這種工作方式。
- 與過去業界重型管線做對照:過去需要 Maya、Nuke、Render Farm、大量專用 FTP 傳輸,「誰能用 Render Farm 的排程」是每天都要協調的事;現在的設定完全不需要這麼龐大的基礎設施,也不再需要等待。這個方向是長期摸索後才定案的。
- 近期與團隊/合作夥伴持續討論的主題:工具/平台本身的備援、人員知識傳承、流程、分享機制。
- 具體案例:不同協作者/模型對同一段程式碼會有不同的分析觀點(架構層面,非僅表面風格),目前的解法是「各試一次,快速得到結果,再依結果修正」。
- 程式開發方向初步評估以 Claude Code 為核心工具,理由包括:不需龐大硬體、適合遠端協作、適合先確立設計邏輯再轉譯為程式架構的工作模式;但也明確意識到需要備案(避免單一工具/單一人員依賴)。
- 今日面試一位候選人因理念不一致而未繼續深談——明確與能力無關,純粹是工作理念/價值觀上的不合。
